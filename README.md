# Restaurant Reservation Management System

A SQL Server database for a group of restaurants — restaurants, menus, tables,
customers, reservations, orders and staff — with the queries, views, functions,
stored procedures, trigger and indexes required by the project, plus an automated
integration-test suite.

## Build the database

Run against a SQL Server instance, in order:

```
00_create_database.sql     -- drops and recreates the database
01_create_tables.sql       -- schema (8 tables + AuditLog)
02_seed_data.sql           -- seed data
```

Then run any file in `queries/` or `query-plans/`. Views, functions, procedures and
the trigger use `CREATE OR ALTER`, so they can be re-run freely.

## Layout

| Path | Contents |
|------|----------|
| `00`–`02_*.sql` | Create database, schema, seed data. |
| `queries/` | Requirements 1–16: queries, views, functions, procedures, trigger. |
| `query-plans/` | Requirements 17–19: query plans, indexes, and plan screenshots. |
| `diagrams/` | ER diagram. |
| `RestaurantDb.IntegrationTests/` | Automated tests (see below). |

Each file is named after its requirement number.

## Seed data

50 restaurants, 400 customers, 100 tables, 1000 menu items, 100 employees,
500 reservations, 500 orders, 1500 order items. Values are generated by a
deterministic hash, so the data is varied but reproducible.

## Tests

The integration tests start a real SQL Server in Docker, build the database from the
scripts above, and assert their behaviour (schema, seed integrity, and every query,
view, function, procedure, trigger and index). Requires the .NET 10 SDK and Docker.

```
dotnet test
```
