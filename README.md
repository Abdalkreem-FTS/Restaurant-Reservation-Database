# Restaurant Reservation Management System (PostgreSQL)

A PostgreSQL port of the restaurant database — restaurants, menus, tables, customers,
reservations, orders and staff — with the queries, views, functions and trigger
required by the project.

## Build the database

1. Run `00_create_database.sql` against the **`postgres`** database (PostgreSQL cannot
   drop the database you are connected to).
2. Connect to the new database: `\c restaurantreservationdb`
3. Run `01_create_tables.sql`, then `02_seed_data.sql`.
4. Run any file in `queries/` or `query-plans/`.

Views, functions and the trigger use `CREATE OR REPLACE`, so they can be re-run freely.
Unquoted identifiers fold to lower case (`RestaurantId` becomes `restaurantid`).

## Layout

| Path            | Contents                                                        |
| --------------- | --------------------------------------------------------------- |
| `00`–`02_*.sql` | Create database, schema, seed data.                             |
| `queries/`      | Requirements 1–16: queries, views, functions and trigger.       |
| `query-plans/`  | Requirements 17–19: query plans, indexes, and plan screenshots. |
| `diagrams/`     | ER diagram.                                                     |

Each file is named after its requirement number.

## Seed data

50 restaurants, 400 customers, 100 tables, 1000 menu items, 100 employees,
500 reservations, 500 orders, 1500 order items. Values are generated by a
deterministic hash, so the data is varied but reproducible.

## Notes

Requirements 13–15 are functions rather than stored procedures, because a PostgreSQL
procedure cannot return a result set.
